# my_test_agent — экспериментальный ADK-агент по экономии токенов

Агент на **Google ADK** + **LiteLLM**, который проверяет, можно ли резко удешевить
длинные диалоги без потери качества ответа. Формально это «эхо-агент» (возвращает
текст пользователя), поэтому в метриках не смешивается качество генерации и эффект
оптимизаций контекста.

**Вся логика оптимизаций вынесена в отдельный пакет [`agent-harness`](../agent-harness)** —
здесь остаются только сборка агента и настройки провайдера.

## Ключевое разделение: сушка ≠ эмоция

Два механизма работают по разным осям и не должны путаться:

| | **Сушка** (`TextSparsifier`) | **Эмоциональный анализ** (`EmotionAnalyzer`) |
|---|---|---|
| над чем | форма одного текста | тон высказывания |
| что делает | убирает слова-связки и «воду», дробит сложные предложения | определяет метку эмоции, кладёт её в `state` |
| экономит | токены на каждый запрос | ничего (это про качество ответа) |
| обратимость | **нет** — удалённые слова теряются | **да** — оригинал лежит в леднике |

Сушка **не удаляет эмоции** — она удаляет вводные слова и связки. Эмоция уходит из
текста в структурированное поле (`state["current_emotion"]`), а не выбрасывается:
модель получает «сухой» факт плюс готовую метку тона, вместо того чтобы выводить
тон из формулировок.

## Компоненты harness

Все модули — реализации общих интерфейсов (`core/interfaces.py`: `PreProcessor`,
`PostProcessor`, `ToolGuard`). Специфика ADK изолирована в адаптере, поэтому тот же
`TextSparsifier` можно переиспользовать с любым другим фреймворком.

| Модуль | Файл | Что делает |
|---|---|---|
| `SlidingWindow` | `modules/window.py` | В окно LLM попадают только последние `max_events` событий (`events[-N:]`) |
| `TextSparsifier` | `modules/sparsifier.py` | Regex-сушка: 10 слов-связок + замена «потому что / так как / , и / , а» на точки |
| `EmotionAnalyzer` | `modules/analyzer.py` | `Aniemore/rubert-tiny2-russian-emotion-detection` (transformers), возвращает метку |
| `ColdStorage` | `modules/storage.py` | Дописывает оригинал (до сушки) в `cold_storage.jsonl`: `session_id`, `ts` (UTC), `role`, `text` |
| `ShellCommandGuard` | `modules/guard.py` | Regex deny-list для `run_shell_command` / `execute_command` (`rm -rf`, `mkfs`, `dd if=`, fork bomb, `curl \| bash`, …) |
| `SafeToolGuard` | `modules/guard.py` | Allow/deny списки по именам инструментов (в этом агенте не подключён) |
| `ADKAgentCallbacks` | `adapters/adk.py` | Переводит модули на язык колбэков ADK |

### Лексикон эмоций

Модель отдаёт 7 меток (`id2label` в конфиге модели): `neutral`, `happiness`,
`sadness`, `enthusiasm`, `fear`, `anger`, `disgust`.

В `TONE_HINTS` (`agent.py`) описаны 6 из них — все, кроме `neutral`. Это не пропуск:
нейтральный тон не нуждается в подсказке, `TONE_HINTS.get("neutral")` возвращает
`None`, и в сообщение ничего не добавляется.

⚠️ У модели `problem_type = multi_label_classification`, а пайплайн берёт
`[0]` — то есть один топ-лейбл. Для фразы со смешанным тоном («устал, но
справляемся») выбирается доминирующая метка, а не обе.

## Как это работает при каждом ходе

```
сообщение пользователя
        │
        ▼
before_model  (adapters/adk.py)
  0. если state["_processed"] → выход (защита от повторного наложения)
  1. ЛЕДНИК: оригинал последнего user-события → cold_storage.jsonl
  2. ИСТОРИЯ: по всем событиям сессии
        role = user | model
        для user: эмоция → state["current_emotion"], затем сушка текста
  3. ОКНО: events[-10:]
  4. ТОН: [Tone hint: ...] → в конец последнего user-сообщения окна
  5. llm_request.contents = новое окно;  state["_processed"] = True
        │
        ▼
   LLM (статичная инструкция → провайдер может кэшировать промпт)
        │
        ▼
after_model
  • пусто или error_code → спасательный круг: в ответ подставляется
    последнее сообщение пользователя, state["error_count"] += 1
  • успех → лог ответа + метрики prompt/cached tokens
  • финал (без function_call) → state["_processed"] = False
        │
        ▼
before_tool (если подключены tools)
  • любой guard вернул False → {"error": "Tool '...' blocked by security guard."}
```

Порядок «оригинал → ледник, потом сушка» принципиален: в холодное хранилище
уходит невысушенный текст, так что из горячего контекста удалять связки безопасно.

## Статичная vs динамическая инструкция

`get_static_instruction()` возвращает одну и ту же строку на любой ход — провайдер
может закэшировать системный промпт. Тон передаётся **не** через инструкцию, а через
короткий `[Tone hint: ...]` в конце последнего сообщения.

Это осознанный отказ от прежней схемы: в `docs/README.md` сохранилась историческая
версия с `get_dynamic_instruction()`, где тон подшивался в системный промпт и из-за
этого ломал кэш (первый прогон на Яндексе: **6.74 ₽**).

## Провайдеры

Переключаются переменной `AI_PROVIDER` в `.env` (`get_llm_model()`):

| | `yandex` (по умолчанию) | `selectel` |
|---|---|---|
| ключи | `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`, `YANDEX_API_BASE` | `SELECTEL_API_KEY` |
| модель | `openai/gpt://{folder}/deepseek-v4.1-flash/latest` | `openai/deepseek/deepseek-v4.1-flash` |
| отключение reasoning | `reasoning_effort="none"` | `reasoning_effort="off"` |

Синтаксис отключения разный — он «родной» для каждого провайдера, подстановка
чужого значения не сработает. Неизвестный `AI_PROVIDER` → `ValueError`.

## Результаты экспериментов

Оба замера — 15 сообщений, один и тот же код. Числа взяты из отчётов в `docs/`.

| Параметр | Selectel | Yandex |
|---|---|---|
| Входные токены | 2 633 | 2 803 |
| Выходные токены | 124 | 139 |
| Reasoning | 0 | 0 |
| Кэш (чтение) | 1 152 | 0 |
| **Стоимость** | **0.06 ₽** | **0.91 ₽** |

Выводы:

1. **Плато подтверждено.** Расход входных токенов не растёт с длиной сессии — окно
   и сушка дают одинаковый результат у обоих провайдеров (разброс в пределах
   погрешности).
2. **Разница в чеке — это тариф, а не поведение модели.** ~15× между провайдерами
   совпадает с отношением цен (~20 ₽/Мтокенов против ~300 ₽/Мтокенов).
3. **Reasoning отключен** — 0 токенов на «мысли» в обоих замерах.

### Кэш промпта: проверено, и он не наш инструмент

`cache_probe.py` — три прогона по Яндексу (`--only yandex`), сырые `usage` в
`cache_probe_*.jsonl`.

| Прогон | Префикс | 1-й запрос | 2-й запрос |
|---|---|---|---|
| базовый | 1182 | cached=1024 | cached=1024 |
| TTL, пауза 120 с, `--fresh` | 1197 | cached=0 | cached=1024 |
| TTL, пауза 300 с, `--fresh` | 1197 | cached=0 | cached=1024 |
| TTL, пауза 450 с, `--fresh` | 1197 | cached=0 | cached=1024 |
| TTL, пауза 900 с, `--fresh` | 1197 | cached=0 | cached=1024 |
| порог, `--repeat 43` | 555 | cached=0 | cached=0 |

Установлено:

1. **Яндекс кэширует**, блок выравнивается по **1024 токена**.
2. **Порог ≈ 1024 токена.** При 555 токенах кэш молчит на обоих запросах —
   хотя живой кэш на 1024 токена в этот момент существовал и начинался с тех же
   слов. Значит считается длина совпадаемого блока, а не наличие записи.
3. **Хедер `OpenAI-Project` кэш не ломает** — запрос с ним попал в кэш,
   прогретый запросом без него. Гипотеза про LiteLLM снята.
4. **Кэш переживает 900 секунд (15 минут)** простоя. `--fresh` подтвердил, что соль исключает попадание в прошлый кэш: 1-й запрос `cached=0` на каждом прогоне, 2-й `cached=1024`. Точная граница не измерена — это «TTL ≥ 15 мин от создания». Для диалога между ходами (1–5 мин) это значительный запас.

Возможное поведение: если при каждом попадании в кэш TTL продлевается (TTI — Time-To-Idle), а не истекает по времени создания (TTL), то кэш может жить бесконечно в рамках диалога. Мы этого не проверяли — каждый прогон создаёт новый кэш. Для практических целей этого достаточно: кэш живёт ≥ 15 мин. Дальнейшее уточнение — academic interest.

**Почему это не применяется к нашей архитектуре — две независимые причины.**

*Структурная:* кэш работает по **префиксу**, а скользящее окно берёт
`events[-N:]`, то есть каждый ход **сдвигает начало** окна. Стабильная префиксная
часть — только системная инструкция:

```
ход 10:  INSTR e1 e2 ... e10
ход 11:  INSTR e2 e3 ... e11        ← общее: только INSTR
```

Увеличение `max_events` не помогает: история в окне не становится префиксом,
она остаётся скользящим хвостом. Кэш может покрыть только инструкцию
(~70 токенов) — ниже порога в 15 раз.

*Экономическая:* чтобы кэш включился, префикс нужно раздуть до 1024+ токенов.
Тогда 15 ходов по ~1182 токена вместо текущих 187:

| Тариф | Сейчас (2 803 токена) | С префиксом 1182 (17 730 токенов) |
|---|---|---|
| Яндекс ~300 ₽/М | 0.84 ₽ | **5.32 ₽** |
| Selectel ~20 ₽/М | 0.06 ₽ | **0.35 ₽** |

Раздувание префикса ради кэша дороже отказа от кэша в **6 раз**. При этом
потолок выгоды кэша — даже 100% входных токенов — это 0.84 ₽ на весь диалог,
меньше рубля. Кэш — рычаг для тех, чей контекст **нельзя** укоротить (RAG-чанки,
схемы инструментов, много few-shot). Наша архитектура контекст укорачивает,
поэтому для неё главный рычаг — само окно и отключение reasoning, а не кэш.

⚠️ Вывод «кэш не окупается» держится на двух допущениях: ставка за
кэшированный токен Яндекса ≈ ставке за обычный (записано в отчёте от 3 ноября,
по тарифу не сверялось) и отсутствие длинной неизбежной инструкции. Если у
боевого агента инструкция на тысячи токенов есть сама по себе — кэш становится
выгодным, и окно перестаёт мешать.

Исследование TTL можно продолжить: проверить, продлевается ли TTL при каждом попадании в кэш (TTI — Time-To-Idle), или умирает через фиксированное время от создания (TTL). Начать с паузы > 900 с и увеличивать.

Сырые логи прогона на Selectel — в `cold_storage-Selectel.zip` (рядом с `agent.py`);
в дерево проекта ниже он не включён, это артефакт эксперимента, а не часть кодовой базы.

## Установка

```bash
python -m venv .venv && source .venv/bin/activate

# harness — локальный пакет, ставим в editable-режиме из соседней папки
pip install -e ../agent-harness[adk]
pip install tiktoken sentencepiece
```

`[adk]` тянет `google-adk`, `litellm`, `transformers`, `torch`, `python-dotenv`.
Первый запуск скачает модель эмоций (~25 МБ) из HuggingFace.

## Настройка окружения

Создайте `.env` рядом с `agent.py`:

```dotenv
AI_PROVIDER=yandex

# Yandex AI Studio
YANDEX_API_KEY=...
YANDEX_FOLDER_ID=...
YANDEX_API_BASE=https://llm.api.cloud.yandex.net/v1

# Selectel AI Gateway (если AI_PROVIDER=selectel)
SELECTEL_API_KEY=...
```

## Запуск

```bash
adk web                    # веб-интерфейс ADK Dev UI
adk run my_test_agent      # интерактивный чат в терминале
```

Локальный замер токенов (три варианта одной фразы: обычный / разреженный / предикаты):

```bash
python measure_tokens_local.py
```

## Известные особенности

- **Анализ эмоций — по всей истории каждый ход.** `_process_history()` проходит по
  всем `session.events` и вызывает классификатор для каждого user-события;
  `state["current_emotion"]` перезаписывается, поэтому в итоге остаётся эмоция
  последнего сообщения. Токены LLM окном ограничены, а локальные вычисления — нет:
  стоимость растёт линейно с длиной сессии. В окне достаточно последних 10 событий,
  и это явный кандидат на оптимизацию.
- **`SlidingWindow.process()` — заглушка.** Реальная логика в `apply_to_history()`;
  одиночный текст окно не сокращает.
- **`AgentWrapper` (`core/wrapper.py`) этим агентом не используется** — альтернативный
  фреймворк-независимый путь для агентов без колбэков.
- **`tools=[]`** — защита `ShellCommandGuard` подключена и работает через
  `before_tool_callback`, но пока проверять нечего. Колбэк останется активным после
  добавления инструментов.
- **Спасательный круг маскирует сбои.** При пустом ответе в чат попадает реплика
  пользователя — по одному ответу нельзя отличить «сработало» от «API упал».
  Смотрите на `state["error_count"]` и на `⚠️` в логе.
- **Эмодзи и `print`-логирование** — наглядность эксперимента, не продакшен-логи.
